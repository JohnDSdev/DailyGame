Why old code was shaped like a piece of cardboard

An 80-column punched card was a physical record format before it became a programming convention. FORTRAN inherited the card's geography so literally that different parts of a line meant different things depending on where the holes sat.
punched cards • IBM • FORTRAN • fixed columns

Take an old FORTRAN card and the source code is not merely printed on it. The card is part of the language interface. Columns 1–5 are for a statement number. Column 6 says whether the statement continues from the previous card. The program text occupies columns 7–72. The last eight columns can be used for identification.

The Smithsonian has a surviving CDC 88157 card printed for FORTRAN with exactly those fields. IBM's own 1401 FORTRAN manual gives the same layout: statements in columns 7–72, columns 73–80 ignored by the processor and available for card numbers or other identifiers. If a deck landed on the floor, those spare columns could suddenly become rather valuable.

Before there were 80 columns

Herman Hollerith's census cards came first. The U.S. Census Bureau used his electromechanical system for the 1890 census. Clerks transferred answers from census schedules onto punched cards, and a reader used metal pins passing through the holes to close electrical circuits. The machine then counted or cross-tabulated the recorded traits.

Those early cards were not the later 80-column IBM card. IBM's history of the format describes a progression through cards with fewer, larger round holes. By the late 1920s IBM was using 45 columns. Demand for more storage created a fairly literal problem: the card had no room left to grow.

In 1928 IBM chose a design developed by Clair D. Lake's team that replaced the round holes with smaller rectangular punches. The familiar card kept roughly the same physical footprint but fit 80 columns across it. IBM says the competing proposal from J. Royden Pierce would instead have encoded more information into the existing round-hole layout. Lake's design required new punching and reading equipment, but it was straightforward to implement and doubled the number of columns.

The diagram makes the oddest part of the system easier to see. A decimal digit can be represented by one punch in its numbered row. Letters use combinations. A through I pair the 12-zone punch with rows 1 through 9; J through R use the 11-zone; S through Z use the 0-zone with rows 2 through 9. One column is one character position, but a character may need more than one hole.

The card became syntax

When IBM developed FORTRAN for the 704 in the 1950s, programmers prepared source on these cards. The original FORTRAN reference manual says the statements themselves were punched in columns 7–72. A C in column 1 made a card a comment. Columns 73–80 were not read by FORTRAN and could carry identifying information.

That left 66 columns for the statement itself. Continuation cards extended a long statement, with column 6 marking that the new card belonged to the previous one. The Smithsonian card is a nice physical reminder that this was not an abstract formatting rule invented by a style guide. A keypunch operator could see the labeled fields on the stock.

The convention survived the disappearance of the hardware that created it. Fixed-form Fortran compilers still understand the old field positions. Modern Intel Fortran documentation, for example, describes columns 1–5 as the label field, 6 as continuation, 7–72 as statement text, and 73–80 as sequence numbers in fixed source form. The compiler can also be told to extend the statement field to column 132, which is a very software-era solution to a cardboard-era limit.

Eighty was a machine dimension before it was a screen dimension

It is tempting to work backward from the familiar 80-character terminal and imagine that punched cards copied some natural width for text. The chronology runs the other way. IBM introduced its 80-column card in 1928, decades before video terminals became ordinary programming equipment.

That does not mean every later 80-column convention has one clean ancestry. Hardware designers reused convenient numbers for different reasons, and software accumulated its own limits. But in FORTRAN's case there is no mystery. The language's fixed columns map directly onto a physical 80-column record. You can still compile source whose left margin is shaped by where a 1950s keypunch put holes in stiff paper.
